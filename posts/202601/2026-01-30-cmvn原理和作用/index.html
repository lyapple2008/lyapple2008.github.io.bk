这里用的是最常见、也是最“朴素”的 CMVN（Cepstral Mean and Variance Normalization）实现，而且是离线（或预计算）CMVN，不是滑窗、也不是在线递推版本。

我们直接对你选中的这段代码拆开看它“到底是哪一种”。

代码回顾（核心一行）#

1

feats.data[idx] = (out_feats[i][j] + cmvn.cmvn_means[j]) * cmvn.cmvn_vars[j];

1️⃣ 这是哪一类 CMVN？#

✔ 类型结论#

全局 CMVN（Global CMVN / Offline CMVN）

  • mean 和 var 提前算好
  • 推理阶段 只做线性变换
  • 没有时间维上的滑窗
  • 没有递推更新（不是 online CMVN）

2️⃣ 数学形式对应哪种？#

标准 CMVN 的两种常见写法：

标准写法（教科书）#

[ y = \frac{x - \mu}{\sigma} ]

你这段代码实际等价于👇#

[ y = (x + \text{mean}) \times \text{var} ]

注意这里的：

  • cmvn_means[j] 不是均值 μ
  • cmvn_vars[j] 不是方差 σ²

而是 已经被预处理过的参数：

1
2

cmvn_means[j] = - μ[j]
cmvn_vars[j]  = 1 / σ[j]

👉 所以这是一个 “把减法和除法提前折叠”的 CMVN

这样做的好处是：

  • 推理时 无减法 / 无除法
  • 非常适合 端侧 / 移动端 / SIMD / ARM NEON
  • 和 Kaldi / FunASR / WeNet 的部署方式完全一致

3️⃣ 作用维度：在 LFR 之后做#

注意 index j 的范围：

1

j < feats.lfr_m * feats.n_mel

说明：

  • CMVN 是在 LFR（Low Frame Rate）之后做的
  • 对象是： 👉 拼接后的 lfr_m × n_mel 特征

这和 FunASR / Paraformer 的做法是一致的：

先 fbank → 再 LFR → 再 CMVN

而不是对原始 fbank（n_mel）直接 CMVN。

4️⃣ 是不是 sliding-window / online CMVN？#

❌ 都不是

代码里完全没有：

  • 时间维统计（mean over time）
  • 滑动窗口
  • 递推更新（EMA / Welford）

所以它不适合：

  • 真·无限流实时统计
  • 语音一边进一边动态算均值

而是：

模型训练阶段统计 → 导出 cmvn 参数 → 推理阶段固定使用

5️⃣ 和 Kaldi / FunASR 的关系#

几乎 1:1 对应：

  • Kaldi 的 ApplyCmvn
  • FunASR runtime 中的 CMVN
  • WeNet / Paraformer ONNX runtime

尤其是这行写法：

1

(x + mean) * var

是典型 Kaldi-style CMVN

6️⃣ 总结一句话版本#

这是 LFR 之后的、使用预计算 mean / inv-std 的全局（离线）CMVN，实现上是 Kaldi / FunASR 同款的“折叠版” CMVN，不是 sliding-window，也不是 online CMVN。
